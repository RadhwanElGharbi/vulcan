# Deterministic dataset fetching audit — 2026-09-17

The current pipeline is a useful acquisition prototype, but `passed` does not yet mean complete, reproducible, or suitable for a particular analysis. The recommended change is a versioned, deterministic **discover → plan → confirm → execute → validate → publish** contract. No model should select sources, invent metadata, repair data, or decide acceptance.

This is an audit and proposed design, not an implementation. Scope: the local backend adapters, orchestration, processing, validators, metadata, cache/job handling, frontend catalogue and fetch controls, and existing Waterloo-Preview sidecars. Provider documentation was checked where scientific interpretation matters. No new fetch job was run and no project data was modified. Isolated validator probes used mocked inspection results; they are not end-to-end provider tests.

**Existing capabilities worth keeping**

The backend has explicit adapters, job/category staging, parallel downloads, GDAL reprojection and polygon clipping, nearest-neighbour land-cover resampling, vector geometry repair, raw SHA-256 generation, raw/processed sidecars, persisted job state, and progress/error reporting. ArcGIS acquisition uses object-ID batches rather than relying only on offset pagination. CLSS cache reuse verifies a stored checksum.

The frontend already has an optional dataset-information view containing provider, access, coverage/resolution, temporal start/end, update frequency and a URL. These are catalogue fields, not an AOI-specific discovery result. The fetch action submits immediately; it does not confirm a frozen source/version/processing plan. Relevant code: [DatasetCoverageDialog.tsx](../../apps/web/src/components/Project/DatasetCoverageDialog.tsx:1113), [information fields](../../apps/web/src/components/Project/DatasetCoverageDialog.tsx:1561), [catalogue API](../../apps/api/api/projects.py:1350).

**Prioritized findings**

| P0 | Source choices are free-text labels. `validate_source` does not validate DEM choices and checks keywords rather than complete product variants. | P0 | [3DEP acquisition](../../apps/api/api/dataset_fetch/fetchers.py:250) makes one TNM query, does not exhaust pagination, skips failed downloads, and can substitute 30 m SRTM when 1 m 3DEP is absent. | P1 | [Processing](../../apps/api/api/dataset_fetch/processing.py:11) does not specify a final output grid. Prefer one analytical warp from preserved source data. Report intersecting native cells and flag an AOI smaller than a source cell; retaining a cell does not create local detail. |
| P1 | Copernicus input paths are appended in `as_completed` order before mosaicking ([fetchers.py](../../apps/api/api/dataset_fetch/fetchers.py:170)). SoilGrids uses a mutable `/latest/` VRT; OSM queries live services without a snapshot date. The runtime is not fully locked, and processing uses all CPU threads. | Sort assets and overlapping-tile precedence explicitly. Pin source versions or retain immutable response bytes and their hashes. Pin GDAL/PROJ dependencies, transformation grids and execution settings. | P1 | [Vector validation](../../apps/api/api/dataset_fetch/validation.py:86) permits unknown CRS with a warning. ArcGIS reports the requested ID count without reconciling the returned IDs. | Verify CRS, geometry/schema, duplicate IDs, feature receipts and clipping. Distinguish `verified_empty`, `incomplete_response`, `unsupported_region` and `failed`. An empty result is valid only after a complete successful query. |
| P1 | [OSM conversion](../../apps/api/api/dataset_fetch/fetchers.py:1064) retains only ways with geometry and a selected tag subset; the Overpass source response, endpoint and timestamp are not retained in fetch metadata. | Specify the supported geometry/query scope, preserve original tags and source payload, record endpoint, query, snapshot/base timestamp and feature versions where available. | P1 | [_dataset_ready](../../apps/api/api/dataset_fetch/job_state.py:383) trusts file existence, a sidecar and size, not AOI/source/processing fingerprints or checksum validity. The isolated probes are reproducible with `python tests/probe_fetch_audit.py`; results are in [fetch-audit-probes.json](../../tests/fetch-audit-probes.json). They demonstrate acceptance-policy gaps, not that the existing Waterloo files are corrupt.

**What “deterministic” must mean**

Given the same canonical AOI, selected product/version, saved discovery snapshot, explicit `as_of` time, processing recipe, policy version and toolchain, ZEUS must produce the same source plan and acceptance decision. Parallel completion order must not affect selection, mosaicking or metadata ordering. If a rule uses age, its reference time is an input rather than an implicit call to the current clock.

Live networks can change. Repeating a query called “latest” is not reproducibility. A source without immutable versions needs a retained snapshot and a clear `replayable only from retained snapshot` designation. A frozen plan should use asset identifiers and checksums when provided, with ETag/version/Last-Modified recorded as evidence rather than automatically treating an ETag as a cryptographic checksum. VRT sources require the identities of the underlying assets too.

Keep operational timestamps and job IDs outside the canonical data-content hash. Canonicalize feature order and geometry representation, and lock the numerical environment for strict replay. Identical numerical arrays do not automatically imply identical GeoTIFF/GeoPackage bytes because containers can contain timestamps and ordering differences. Claim byte-for-byte reproducibility only after testing it.

**The pre-fetch confirmation contract**

Introduce `POST /projects/{project}/dataset-fetch/plan`. It validates the AOI, resolves sources, saves the discovery response, runs preflight rules and returns an immutable `plan_id` plus `plan_hash`. The existing execution endpoint should accept that plan identity and the IDs of acknowledged warnings. It should not reinterpret free-text source labels or re-run “Auto” selection after confirmation. A changed AOI, recipe, source identity or expired discovery requires a new plan.

The existing UI can keep its design and show one review card per selected dataset before a final **Confirm fetch** button:

| User-visible information | Required interpretation |
|---|---|
| Exact product, publisher, version, official link and delivery endpoint | Distinguish the original publisher from a mirror or API host. Show the actual resolved source for Auto. |
| Observation/acquisition period | Show date range, precision and per-tile variation where supplied. Explicitly say unknown when absent. |
| Release date, service snapshot date, last verified time and update cadence | These are separate facts. An update cadence is not a guarantee that this AOI was surveyed recently. |
| Native grid spacing, native units and documented accuracy | Do not equate grid spacing with positional accuracy. For vectors use scale/accuracy if documented; otherwise “not specified”, not a fabricated pixel resolution. |
| Planned output grid, CRS and resampling | Show target spacing separately, including an upsampling warning and vertical CRS/units for elevation. |
| AOI coverage and expected missing regions | Before download this usually means catalogue-footprint coverage, not measured valid-pixel coverage. Label the method and unknowns. |
| Meaning of values | Band/property, unit, scale/offset, categorical legend, soil depth/statistic, or hazard scenario. |
| License, attribution, access requirements and usage restrictions | Product-specific evidence and a verification date. Software licensing does not override dataset licensing. Unknown rights must not be guessed. |
| Download/output/temporary-space estimates and cache behavior | Distinguish exact sizes from estimates, and source reuse from fresh discovery. |
| Warnings, limitations and acceptance profile | Show what will block publication, what needs acknowledgement and what remains unverified until download. |

The plan should record `source_id`, `source_version`, `adapter_version`, `catalogue_version`, `aoi_hash`, asset receipts, snapshot/query identifiers, `as_of`, temporal evidence, native schema/units, target-grid recipe, masks, expected counts, `quality_policy_id/version`, warning IDs and a toolchain fingerprint. Pre-fetch checks cannot guarantee actual pixel validity in an unexamined remote file; confirmation approves the recipe and quality gates, and post-fetch validation determines whether the output may be published.

**Provider-specific corrections**

- **Copernicus GLO-30:** identify the product as a surface model and carry its vertical reference. It includes buildings and vegetation, so it must not be described as bare-earth terrain. Product metadata should supply acquisition ranges and infill limitations, rather than assigning every pixel the profile's “2021” date. [Copernicus product description](https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM), [DEM reference documentation](https://documentation.dataspace.copernicus.eu/APIs/SentinelHub/Data/DEM.html).
- **USGS 3DEP:** enumerate all pages, deduplicate product IDs, choose overlap precedence by an explicit rule, preserve tile dates and source CRS/vertical metadata, and reconcile all planned downloads. The provider's API supports paged discovery. [USGS TNM API documentation](https://ghsc.code-pages.usgs.gov/lhp/pfdf/api/data/usgs/tnm/api.html).
- **WorldCover:** use explicit 2020/v100 and 2021/v200 identities. Preserve the class legend and nearest-neighbour resampling. Observation year and release date differ: the 2021 product was released in October 2022. Its reported global accuracy is not a local guarantee, and the two releases used different algorithms, which matters for change analysis. [WorldCover access and limitations](https://esa-worldcover.org/en/data-access), [release information](https://esa-worldcover.org/en/about/about).
- **SoilGrids:** show native 250 m spacing, property, depth and mean/quantile. Declare storage units and conversion explicitly: SOC is stored in dg/kg and division by 10 gives g/kg; clay/sand storage in g/kg converts to percent by division by 10. Preserve source values or apply a recorded conversion, never leave it implicit. Offer quantile uncertainty as an explicit additional product, not an inferred confidence score. [ISRIC layer documentation](https://docs.isric.org/globaldata/soilgrids/SoilGrids_faqs_01.html), [product overview](https://docs.isric.org/globaldata/soilgrids/).
- **GEM PGA:** correct the release metadata and expose units in fractions of g, 475-year return period / 10% exceedance in 50 years, and reference-rock conditions. The selected 2023 record describes interpolation from points roughly 6 km apart; a smaller output pixel is not evidence of local hazard detail. Check the published archive checksum. A newer release being available should trigger a discoverable upgrade option, not silently change a confirmed plan. [Selected GEM record](https://zenodo.org/records/8409647).
- **OSM / Canadian services:** live-service extraction time is not observation age. Preserve service response timestamps or state their absence. For AOIs spanning Canada and another country, country membership alone must not select a Canada-only source for the entire AOI; resolve coverage by intersection and report missing regions or explicitly plan a mixed-source mosaic.

**Proposed quality policy**

There is no universal numeric threshold that makes all geospatial data “up to standard.” Use named, versioned profiles. A proposed `complete_extract_v1` should require verified mandatory assets, valid CRS/schema, all mandatory checks executed, no unexpected non-finite values, correct units, no unaccounted-for missing AOI coverage, and no unexplained feature loss. Expected outside-domain cells, water masks and pixel-boundary conventions must be part of the plan, not excuses added after a download fails.

A proposed `partial_extract_v1` may allow a lower explicitly chosen coverage threshold, but must disclose the actual coverage and gap mask and require warning acknowledgement. Such thresholds are ZEUS product policy, not externally certified accuracy standards. Constant coarse-grid values and verified-empty vector results need category-specific rules. A high-level status should be `pass`, `pass_with_acknowledged_warnings`, `fail` or `not_evaluated`, backed by rule IDs, thresholds, measured values, units, evidence and policy version. Never present an unexecuted check as a pass.

Validate raster band count/type, mask and NoData, finite values, category ranges, dimensions, grid registration, CRS and valid area. Validate vector schema, IDs, geometry validity/types, repair changes, AOI intersection, duplicates and complete source receipts; topology rules must be appropriate to the category. Run exact checks in bounded blocks where correctness requires a complete scan. Optional sampling must declare its deterministic pattern and cannot substantiate complete-coverage claims.

Use validated Cloud Optimized GeoTIFFs for distributable rasters when remote/interactive access is required; tiled GTiff alone is not proof of COG conformance. Keep GeoPackage for vectors and expose a schema-validated STAC-compatible asset catalogue with temporal, spatial and lineage metadata where applicable. Format conformance and scientific suitability remain separate tests. [OGC COG standard](https://docs.ogc.org/is/21-026/21-026.html), [STAC specification](https://stacspec.org/en/about/stac-spec/), [GDAL warp/grid controls](https://gdal.org/en/stable/programs/gdalwarp.html).

**Recommended delivery order and acceptance tests**

1. Unify the source registry, remove model execution, reject unsupported variants, correct dates/units and eliminate unconfirmed product substitution.
2. Add persisted fetch plans and the pre-confirmation review cards. Implement source snapshots, explicit output grids and cache fingerprints together so the UI describes the execution contract truthfully.
3. Add blockwise AOI quality gates, pagination/receipt reconciliation, structured reports and immutable publication with cancellation-safe commit.
4. Lock the toolchain, add provider fixture tests, deterministic replay, format-conformance tests and operational limits.

Required fixtures: 1%-valid and all-NoData rasters; missing statistics/CRS; valid single-cell hazard coverage; invalid land-cover codes; wrong soil units/depth; legitimate empty vectors versus truncated service responses; missing middle DEM tiles; multi-page TNM; ArcGIS missing IDs; OSM error payloads; country-border and antimeridian AOIs; changed source after confirmation; corrupted or wrong-AOI cache; cancellation before publication; shuffled parallel completion and overlapping tiles; source-date unknown; and two replays of the same saved plan. Keep network integration tests separate from immutable fixture tests.
